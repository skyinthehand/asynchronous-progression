# Quickstart: 予選プール進行デジタル管理ツール

本ツールが実装された後、各ユーザーストーリーが実際に動作することを確認する
ための手順。詳細なAPI/データ構造は `data-model.md` と `contracts/` を参照し、
ここでは重複させない。

## 前提条件

- devcontainer内でNode.js 22 / npmが利用可能であること
  (`.devcontainer/devcontainer.json`)。
- `npm install` 実行済み。
- 検証用のstartggトーナメント(またはstartggのテスト/サンドボックス用大会)
  で、検証者自身がTO/admin権限を持っていること、およびPersonal Access
  Tokenを1つ発行済みであること([Authentication][auth-docs]参照)。
- 参考レイアウトファイル `impact_major_4_brackets.pdf`(リポジトリ直下)を
  手元で開けること(印刷レイアウト比較用)。

[auth-docs]: https://developer.start.gg/docs/authentication/

## セットアップ

```bash
npm install
npm run dev   # Vite開発サーバーを起動(既定ポート 5173)
```

devcontainer利用時は、`.devcontainer/devcontainer.json`にVite用ポート
(5173)のフォワーディングが設定されていることを確認する。

## シナリオ1: 注意書きの確認(User Story 1)

1. ブラウザで開発サーバーのURLを開く。
2. **期待結果**: 他の画面より先に注意書きが表示され、内容を確認する操作を
   するまで他の操作に進めない(FR-001)。
3. 注意書きを閉じた後、専用ボタンから再表示できることを確認する(FR-002)。
4. 検証用トーナメントの`Rules`欄に緊急連絡先の記載がない状態にしてから
   次回同期を待ち、警告が表示されることを確認する(FR-003, FR-033)。

## シナリオ2: プール進行のオフライン入力(User Story 2)

1. 管理画面(シナリオ5参照)で対象プールを初期化済みの状態にする。
2. 一般モードで対象プール画面を開き、出欠・離席(開始/終了)・進行担当者名を
   入力する(FR-004〜FR-006)。
3. 対戦カードに結果を入力し、次に着手すべき対戦カードが強調表示されることを
   確認する(FR-007, FR-009)。
4. ブラウザの開発者ツールでネットワークをオフラインに切り替え、上記操作を
   継続してもエラーにならないことを確認する(FR-012)。
5. ページを強制リロード(またはタブを閉じて再度開く)し、直前までの入力内容が
   復元されることを確認する(FR-013、SC-003)。

## シナリオ3: startgg自動同期とオフライン通知(User Story 3)

1. シナリオ2の状態でネットワークをオンラインに戻す。
2. **期待結果**: 一定間隔後、ローカルの変更がstartgg側に反映される
   (`contracts/startgg-graphql-operations.md` M1、FR-015)。startgg側の
   トーナメント管理画面で結果が反映されていることを確認する。
3. 再度オフラインに切り替え、設定した閾値時間を超えて待機し、スナックバーで
   同期不良が通知されることを確認する(FR-016)。
4. オンラインに戻し、通知が解消されることを確認する(User Story 3 AC3)。

## シナリオ4: 予選終了選手への次戦案内(User Story 4)

1. あるプールの全対戦カードを完了させる。
2. **期待結果**: 全対戦を終えた選手が一覧で識別可能になり、後続フェーズの
   組み合わせが取得済みであれば対戦相手・卓番号が具体的に表示される
   (FR-018, FR-019)。
3. Bクラス以下相当のプールでも同様に案内対象となることを確認する(FR-020)。
4. 後続フェーズが未確定の選手については「未確定」と表示されることを
   確認する(edge case)。

## シナリオ5: 管理画面(User Story 5)

1. 一般モードから管理画面への入口を開き、誤ったパスワードでは入れず、
   正しいパスワードで入れることを確認する(FR-026)。
2. 初期化フローで、(1) Personal Access Tokenを入力し管理権限のある
   トーナメント/イベント/フェーズ/プール一覧が取得・選択できること、
   (2) 対象プールを選択できること、(3) 定期同期用トークンを保存できること
   を順に確認する(FR-027)。
3. 一度初期化した後、「対象プールのみ」「トークンのみ」をそれぞれ単独で
   再設定できることを確認する(トークン再入力/プール再選択が不要、FR-028)。
4. 手動ログアウトで一般モードに戻ることを確認する(FR-029)。
5. システム時刻を24時間以上進める(またはテスト用に短縮した設定で代替検証
   する)ことで自動ログアウトを発生させ、通知されることを確認する
   (FR-030, FR-031)。
6. 管理画面で現在の注意書き内容が表示され、startgg側の編集画面への
   リンクが機能することを確認する(FR-032)。

## シナリオ6: 結果の後日修正(User Story 6)

1. 後続の対戦カードが未着手の対戦結果を修正し、反映されることを確認する
   (FR-021)。
2. 後続の対戦カードが既に結果入力済み/進行中の対戦結果を修正しようとし、
   拒否されることを確認する(FR-022)。

## シナリオ7: 印刷用ページ(User Story 7)

1. 対戦カード・結果が入力済みのプールで印刷用ページを開く。
2. 画面を`impact_major_4_brackets.pdf`の該当プールと見比べ、組合せ
   ブラケットの図・ヘッダー(プール名・大会名・日時・種目名・Judge欄)・
   フッター(生成日時)の構成が一致することを目視確認する(FR-023, FR-024)。
3. ブラウザの印刷機能で「PDFに保存」し、操作用UI要素(ボタン等)が含まれて
   いないことを確認する(User Story 7 AC2)。
4. 総当り形式のプールでも、startggの当該形式の印刷レイアウトに準じた
   表示になることを確認する(FR-025)。
