# Quickstart: 次戦サジェストの優先順位修正

本featureが実装された後、次戦サジェストの優先順位が正しく動作することを
確認するための手順。詳細な算出ルールは`data-model.md`と`research.md`を
参照し、ここでは重複させない。`001-pool-progression-tracker/quickstart.md`
の前提条件(devcontainer・`npm install`・startgg検証用トーナメント)を
満たしていることを前提とする。

## セットアップ

```bash
npm install
npm run dev   # Vite開発サーバーを起動(既定ポート 5173)
```

対象プールが初期化済みであること。以下のシナリオは、勝敗ブラケット
(DOUBLE_ELIMINATION)形式のプールで、対戦台数を複数(例: 4)設定した状態を
前提とする。

## シナリオ1: 出場者未確定の対戦が候補から除外される(FR-001)

1. 予選プール開始直後(まだどの対戦も結果が入力されていない状態)で
   対戦カード一覧・組合せ図を確認する。
2. **期待結果**: 次戦候補として強調表示される対戦は、出場者が両方
   あらかじめ確定している初戦(ラウンド1)の対戦のみである。ラウンド2
   以降の対戦(まだ出場者が決まっていない)は一切候補にならない。
3. 一部の参加者が不戦勝(BYE)になっている(片方の枠にしか対戦相手が
   いない)対戦カードがあれば、それも次戦候補にならないことを確認する。
   その不戦勝の対戦は、一覧から直接「〜の不戦勝で確定」ボタンで処理できる
   (次戦候補としての自動提示は行われないが、通常の操作は妨げられない)。

## シナリオ2: プール抜けからの遠さで優先順位が決まる(FR-002〜FR-004)

例: あるプールの組合せ図が、勝者側はWinners Final(WF)を頂点に
Winners Semi-Final(WSF)がその1つ手前、敗者側はLosers Semi-Final(LSF)を
頂点にLosers Quarter-Final(LQF)がその1つ手前、という構造だったとする
(spec.mdの例と同じ)。

1. WSFとLQFの両方が、出場者が両方確定していて未着手の状態になるまで
   結果を入力する(WF・LSFはまだ出場者が確定していない状態を維持する)。
2. 対戦台に空きがある状態で次戦候補を確認する。
3. **期待結果**: WSFとLQF(基準点から距離2)が、より基準点に近い他の対戦
   より優先して次戦候補になる。基準点自体(WF・LSF、距離1)は、この時点
   ではまだ出場者が確定していないため候補にならない。

## シナリオ3: 遠さが同じ場合は敗者側が優先される(FR-005)

1. シナリオ2の状態(WSFとLQFがともに候補になり得る、対戦台に2つ以上
   空きがある)から、対戦台の空きが1つしかない状態にする。
2. 次戦候補を確認する。
3. **期待結果**: WSF(勝者側)ではなくLQF(敗者側)が優先して候補になる。

## シナリオ4: 遠さ・側が同じ場合は組合せ図上で上の対戦が優先される(FR-006)

1. 同じ距離・同じ側(例: 敗者側の同じラウンドに2つの対戦)の対戦が両方
   出場者確定済みで未着手になる状態を用意し、対戦台の空きを1つだけに
   する。
2. 次戦候補を確認する。
3. **期待結果**: 組合せ図(トーナメント表)上でより上に表示されている方の
   対戦が優先して候補になる。

## シナリオ5: 進行可能な対戦が対戦台数に満たなくてもエラーにならない(FR-007)

1. 対戦台を3つ以上設定したプールで、出場者が両方確定していて未着手の
   対戦が1つしかない状態にする。
2. 次戦候補を確認する。
3. **期待結果**: 1つの対戦台にのみ候補が提示され、残りの対戦台には候補が
   提示されない。エラー表示や進行の停止は発生しない。

## シナリオ6: 総当り形式では従来どおり(FR-008)

1. 総当り(ROUND_ROBIN)形式のプールで、複数の対戦カードが未着手のまま
   残っている状態を用意する。
2. 次戦候補を確認する。
3. **期待結果**: 距離に基づく優先順位は適用されず、既存どおり
   ラウンド→識別子の昇順で候補が決まる(本feature導入前と同じ挙動)。

## 参考: 実際のトーナメントデータでの確認

実際にstart.ggと同期した勝敗ブラケット形式のプール(結果が1件も入力
されていない開始直後の状態)で組合せ図を開いた場合、次戦候補として強調
表示されるのは、出場者が両方あらかじめ確定しているラウンド1の対戦の
いずれかに限られる(シナリオ1の期待結果と同じ)。対戦台数を上回るラウンド
1の対戦が存在する場合は、対戦台数の分だけが候補になる。
