# Feature Specification: 次戦サジェストの優先順位修正

**Feature Branch**: `003-next-match-priority-fix`

**Created**: 2026-08-13

**Status**: Draft

**Input**: User description: "次の対戦としてサジェストされるマッチがおかしいため、以下の仕様に修正する。
両者の対戦相手が決まっていないマッチは対象外となる。プール抜けをかけた
最後のマッチから逆算して、もっとも遠いマッチが優先される。例えばプール抜けが
勝者側がWF(Winners Final)で、敗者側がLSF(Losers Semi-Final)だった場合は、
WFとLSFが1、WSFとLQF(Losers Quarter-Final)が2、といったふうに順番がつき、
数字の大きいマッチが優先される。勝者側と敗者側で遠さが同じマッチがあった場合は
敗者側が優先される。同じ遠さで同じ側のマッチが複数存在している場合は上に
表示されているマッチを優先。進められるマッチ(両者の対戦相手が決まっている
マッチ)が対戦台数を満たさない場合は、特に次の対戦としてサジェストされる
マッチはなくてよい。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 進行可能な対戦だけを優先順位に沿って提示する (Priority: P1)

進行担当者は、対戦台が空いた際に次に呼ぶべき対戦カードとして、実際に今すぐ
開始できる(両出場者が確定している)対戦の中から、プール全体の進行が
もっとも早く進むように選ばれた対戦を提示してほしい。まだ片方の出場者しか
決まっていない対戦(先行する対戦の結果待ちの対戦)が誤って提示されることは
あってはならない。

**Why this priority**: 現状、実際にはまだ開始できない対戦(出場者が
そろっていない対戦)がサジェストされてしまうことがあり、進行担当者が
呼び出しても対戦を開始できず現場が混乱する。この修正なしには次戦サジェスト
機能そのものが信頼できない。

**Independent Test**: 出場者がまだ両方は決まっていない対戦カードが存在する
プールで、その対戦が次戦候補として一切提示されないことを確認する。あわせて、
出場者が両方確定している対戦の中から、後述の優先順位規則に沿って正しい対戦が
選ばれることを確認する。

**Acceptance Scenarios**:

1. **Given** 先行する対戦の結果待ちで出場者の枠が埋まっていない対戦カード
   のみが未着手で残っている、**When** 進行担当者が対戦台の空き状況を確認
   する、**Then** その対戦カードは次戦候補として提示されない。
2. **Given** 不戦勝(BYE)によって片方の枠に対戦相手が存在しない(先行する
   対戦を待っているわけではない)未着手の対戦カードが存在する、**When**
   次戦候補を計算する、**Then** その対戦カードは(出場者が確定している側の
   勝ち抜けとして)通常の対戦と同様に次戦候補の対象になり得る。
3. **Given** 勝敗ブラケット形式のプールで、出場者が両方確定している未着手の
   対戦カードが複数存在する、**When** 次戦候補を計算する、**Then** プール抜け
   (そのブラケットの側で優勝相当を決める最後の対戦)から見てもっとも遠い
   (=先行するラウンド数が多い)対戦から優先して候補になる。
4. **Given** 勝者側・敗者側それぞれに、プール抜けの対戦からの遠さが等しい
   出場者確定済みの対戦が1つずつ存在する、**When** 次戦候補を計算する、
   **Then** 敗者側の対戦が優先して候補になる。
5. **Given** 遠さも勝者側/敗者側の別も等しい出場者確定済みの対戦が複数存在
   する、**When** 次戦候補を計算する、**Then** 組合せ図(トーナメント表)上で
   より上に表示されている対戦が優先して候補になる。
6. **Given** 予選プール開始直後で、まだどの対戦も結果が入力されていない(=
   出場者が両方確定しているのは初戦のみ)、**When** 次戦候補を計算する、
   **Then** 出場者が両方確定している初戦の対戦の中からのみ、対戦台数に応じて
   優先順位の高いものが選ばれる。

---

### User Story 2 - 進行可能な対戦が対戦台数に満たなくても支障なく進行できる (Priority: P2)

進行担当者は、今すぐ開始できる対戦の数が空いている対戦台の数より少ない
場合でも、システムが無理に対戦を提示しようとせず、進行の妨げにならないことを
期待する。

**Why this priority**: 対戦台の一部が埋まらない状況は珍しくなく(序盤で対戦数
自体が少ない、進行にばらつきがある等)、そのたびにエラーや不要な催促が出ると
現場の運用に支障が出る。ただし主要な優先順位ロジック(User Story 1)がなければ
そもそも価値を持たないため優先度はP2とする。

**Independent Test**: 出場者が両方確定している未着手の対戦の数が、設定
されている対戦台の数より少ないプールで、余った対戦台には次戦候補が提示
されず、かつエラー表示や進行の停止が発生しないことを確認する。

**Acceptance Scenarios**:

1. **Given** 対戦台が3つ設定されているが、出場者が両方確定している未着手の
   対戦が1つしかない、**When** 次戦候補を計算する、**Then** 1つの対戦台へ
   1件の候補が提示され、残り2つの対戦台には候補が提示されないが、エラーには
   ならない。
2. **Given** 出場者が両方確定している未着手の対戦が1つもない、**When** 次戦
   候補を計算する、**Then** どの対戦台にも候補は提示されず、一覧・組合せ図
   上の強調表示も対象がない状態になる。

---

### Edge Cases

- 総当り(ROUND_ROBIN)形式のプールには「プール抜けの対戦」や勝者側/敗者側の
  区別が存在しないため、本仕様の優先順位規則(プール抜けからの遠さ、
  敗者側優先)は適用されない。総当り形式における優先順位は現行のまま
  (ラウンド→識別子の昇順)変更しない。
- シングルイリミネーション形式のプールには敗者側が存在しないため、「勝者側と
  敗者側で遠さが同じ場合は敗者側を優先」する規則は該当せず、勝者側のみで
  遠さに基づく優先順位が決まる。
- プール抜けの対戦(その側で最後に行われる対戦)自体が、出場者が両方確定して
  いて未着手であれば、通常どおり候補になり得る(遠さの基準点であることと、
  それ自体が優先順位の対象から外れることは別)。
- 対戦台が1つも設定されていないプールでは、対戦台単位の優先順位付けは行わず、
  プール全体で最も優先順位の高い対戦を1件だけ提示する(既存のFR-018の
  フォールバック方針を踏襲する)。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、先行する対戦の結果待ちで出場者の枠が埋まっていない
  対戦カード(=まだ行われていない対戦の結果によって初めて対戦相手が決まる
  対戦)を、次戦候補の対象から除外しなければならない。一方、不戦勝(BYE)に
  よって最初から片方の枠に対戦相手が存在しない対戦(その枠を埋めるはずの
  先行する対戦自体が存在しない対戦)は、対象外にはしない(出場者が確定して
  いる側の勝ち抜けとして、通常の対戦と同様に次戦候補になり得る)。
- **FR-002**: システムは、勝敗ブラケット形式のプールにおいて、各側(勝者側・
  敗者側)ごとに、その側で最後に行われる対戦(プール抜けを決定づける対戦)を
  「遠さ1」の基準点としなければならない。
- **FR-003**: システムは、対戦カードの「遠さ」を、その対戦の勝者・敗者の
  進出先(いずれか近い方)の対戦の遠さに1を加えた値として算出しなければ
  ならない。基準点となる対戦(FR-002)自体の遠さは1とする。
- **FR-004**: システムは、出場者が両方確定している対戦カードを次戦候補と
  する際、遠さの値が大きい(=プール抜けの対戦からより遠い)対戦を、値が
  小さい対戦より優先しなければならない。
- **FR-005**: システムは、遠さが等しい対戦が勝者側と敗者側の双方に存在する
  場合、敗者側の対戦を勝者側の対戦より優先しなければならない。
- **FR-006**: システムは、遠さと勝者側/敗者側の別が等しい対戦が複数存在する
  場合、組合せ図(トーナメント表)上でより上に表示されている対戦を優先
  しなければならない。
- **FR-007**: システムは、出場者が両方確定している未着手の対戦の数が、設定
  されている対戦台の数に満たない場合でも、エラーとして扱ったり進行担当者の
  操作を妨げたりしてはならない。満たせない対戦台には次戦候補を提示しない
  状態を許容する。
- **FR-008**: システムは、総当り(ROUND_ROBIN)形式のプールおよび勝者側/
  敗者側の区別を持たない形式のプールでは、本仕様の遠さに基づく優先順位
  規則を適用せず、既存の優先順位(ラウンド→識別子の昇順)を維持しなければ
  ならない。
- **FR-009**: システムは、対戦台に紐付かない次戦候補(対戦台数が未設定の
  プール向けのフォールバック)についても、FR-001〜FR-006の優先順位規則に
  従って1件を選ばなければならない。

### Key Entities *(include if feature involves data)*

- **対戦カードの遠さ(プール抜けからの距離)**: 対戦カードが、そのブラケット
  の側(勝者側/敗者側)でプール抜けを決定づける最後の対戦から、勝敗の進出先を
  たどって何段階手前にあるかを表す値。値が大きいほど早いラウンドの対戦で
  あることを意味し、優先順位の主要な基準となる。永続化はせず、対戦カード
  一覧から都度算出する(既存の次戦サジェスト計算・組合せ図の詰め直しと
  同じ設計方針)。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 出場者が両方確定していない対戦カードが次戦候補として提示される
  件数は、常に0件である。
- **SC-002**: 進行可能な対戦が複数のラウンドにまたがって存在する状況で、
  プール抜けの対戦からもっとも遠い対戦から順に、空いている対戦台数の分だけ
  次戦候補として提示される。
- **SC-003**: 遠さが等しい進行可能な対戦が勝者側・敗者側の双方に存在する
  場合、敗者側の対戦が次戦候補として選ばれる。
- **SC-004**: 進行可能な対戦の数が対戦台数を下回る状況でも、進行担当者の
  操作(結果入力・対戦台への割り当て等)が妨げられることは一切ない。
- **SC-005**: 予選プール開始直後(結果未入力)の状態で、次戦候補として
  提示される対戦は、必ず初戦(出場者が両方あらかじめ確定している対戦)の
  中から選ばれる。

## Assumptions

- 「先行する対戦の結果待ちで出場者の枠が埋まっていない対戦」と「不戦勝
  (BYE)によって片方の枠に対戦相手が存在しない対戦」は区別する。前者は、
  その枠を埋めるはずの先行する対戦がまだ結果未確定であるために枠が
  空いている状態を指し、次戦候補の対象外とする(FR-001)。後者は、その枠を
  埋めるはずの先行する対戦自体が最初から存在しない(シードやBYEに由来する)
  状態を指し、出場者が確定している側がそのまま勝ち抜ける対戦として、次戦
  候補の対象になり得る。両者は、対戦カードの空いている枠に「結果待ちの
  先行する対戦が存在するかどうか」で区別できる。
- 「プール抜けを決定づける最後の対戦」は、各ブラケットの側(勝者側/敗者側)
  ごとに、そのプール内でその側に属する対戦のうちラウンドが最も進んだ
  ものを指す(何名がプールを抜けるかという別の設定値を新たに導入する
  ものではない)。
- 対戦カードの「進出先」(勝者・敗者がどの対戦へ向かうか)は、既存の
  ブラケット構造の詰め直しロジック(001-pool-progression-trackerの
  組合せ図表示、および002-match-scoring-and-flowの
  advanceWinner/対戦結果の反映)が用いているのと同じ、対戦カード間の
  前後関係(どの対戦の結果がどの対戦の出場者枠を埋めるか)を指す。新しい
  データを保存する必要はなく、既存の対戦カード一覧から都度算出できる。
- 「組合せ図上でより上に表示されている対戦」の判定は、既存の組合せ図
  (トーナメント表)の表示順(001-pool-progression-trackerの表示ロジックが
  算出する縦位置)をそのまま用いる。総当り表など組合せ図を持たない表示
  形式では、この規則は実質的に適用されない(FR-008により対象外のため)。
- 本仕様は002-match-scoring-and-flowで導入した次戦サジェスト機能
  (対戦台単位のサジェスト、結果確定直後のモーダル、スキップ機能等)の
  「どの対戦を優先するか」を決める判定ロジックのみを修正するものであり、
  モーダル表示・スキップ・対戦台の割り当てといった周辺の操作性(FR-017〜
  FR-027)には変更を加えない。
- スキップ済み(次戦サジェストの対象から一時的に外された)対戦の扱いは
  002-match-scoring-and-flowの既存方針(他に候補がある間は後回しにするが
  完全には除外しない)を維持し、本仕様の優先順位規則はスキップされていない
  対戦同士の順序付けに適用される。
