# Quickstart: 対戦結果入力・対戦台呼び出しフローの強化

本featureが実装された後、各ユーザーストーリーが実際に動作することを確認
するための手順。詳細なデータ構造は `data-model.md` と `contracts/` を参照
し、ここでは重複させない。`001-pool-progression-tracker/quickstart.md`の
前提条件(devcontainer・`npm install`・startgg検証用トーナメント)を満たして
いることを前提とする。

## セットアップ

```bash
npm install
npm run dev   # Vite開発サーバーを起動(既定ポート 5173)
```

対象プールが初期化済み(`001-pool-progression-tracker`シナリオ5)であること。

## シナリオ1: スコア入力による結果確定(User Story 1)

1. 対戦カード一覧(ブラケット表示・総当り表のいずれでも可)で、未着手の
   対戦カードを開く。
2. 出場者Aのスコア欄に`3`のみを入力し、出場者Bのスコア欄には何も入力せず
   結果を確定する。
3. **期待結果**: 結果が「Aの勝ち、スコア3-0」として確定する(FR-002,
   FR-004)。
4. 別の対戦カードで、出場者Bの失格(DQ)のみを選択して確定する。
5. **期待結果**: 「Aの勝ち(Bが失格)、スコアDQ-0」として確定する(FR-005)。
6. 別の対戦カードで、両出場者に同じスコアを入力しようとする。
7. **期待結果**: 結果は確定できず、修正を促すメッセージが表示される
   (FR-003)。
8. 両出場者を同時にDQとして入力しようとする。
9. **期待結果**: エラーとして拒否される(FR-006)。

## シナリオ2: 対戦台の設定と割り当て(User Story 2)

1. プール設定(管理画面または進行担当者向け設定)で対戦台数を`3`に設定する
   (FR-011)。
2. 未着手の対戦カードに対戦台番号`2`を割り当てる(FR-012)。
3. **期待結果**: 対戦カードに対戦台2が割り当てられたことが表示される。
4. 別の未完了の対戦カードにも対戦台番号`2`を割り当てようとする。
5. **期待結果**: 割り当てが拒否され、対戦台2が使用中であることが示される
   (FR-014)。
6. 開発者ツールでネットワークをオフラインにし、同期後に再度オンラインへ
   戻す。
7. **期待結果**: 手順2で入力した対戦台番号が、start.gg同期後も消えたり
   古い値に戻ったりしない(FR-016、`contracts/match-result-and-table-schema.md`
   のtableNumber保護)。

## シナリオ3: 次戦サジェスト・呼び出しの変更・スキップ(User Story 3)

1. シナリオ2に続けて、対戦台1に割り当てた進行中の対戦の結果をスコア入力で
   確定する(シナリオ1の手順)。
2. **期待結果**: 結果確定の直後、対戦台1へ次に呼ぶべき対戦カードの候補が
   モーダルで自動的に表示される(FR-022)。
3. モーダル内で対戦台番号を入力せずに「対戦開始」を選ぶ。
4. **期待結果**: 対戦台番号なしでその対戦が「進行中」に変更される(FR-023,
   FR-024)。
5. 別の対戦の結果を確定し、表示されたモーダルで「スキップ」を選ぶ。
6. **期待結果**: 一覧からは消えず、別の未着手の対戦が次戦候補として提示
   される(FR-018)。スキップした対戦は、一覧から直接選べば通常どおり
   開始できる(FR-021)。
7. 結果確定後に表示されたモーダルを、「対戦開始」「スキップ」いずれも
   選ばずに閉じる。
8. **期待結果**: 対戦の状態は変わらず、次に対戦台が空いた際や一覧確認時に
   同じ対戦が改めて次戦候補として提示される(FR-025)。
9. 勝敗ブラケット形式のプールでトーナメント表示(組合せ図)を開く。
10. **期待結果**: モーダルを開かなくても、次戦候補の対戦カードがその場で
    識別できる(FR-026)。
11. プールの対戦台数設定を未設定(null)に戻す。
12. **期待結果**: 対戦台に紐付かない、従来通りの単純な次戦提示に切り替わる
    (FR-018)。

## シナリオ4: 「進行中」ステータスの任意設定(User Story 4)

1. 未着手の対戦カードを「進行中」に設定する。
2. **期待結果**: 一覧上で他の未着手の対戦と区別して表示される(FR-009)。
3. 別の未着手の対戦カードで、「進行中」を経由せず直接スコアを入力して
   結果を確定する。
4. **期待結果**: 問題なく結果が確定する(FR-010)。

## シナリオ5: 既存の同期不良通知との共存

1. シナリオ3の手順2でモーダルを表示させた状態のまま、開発者ツールで
   ネットワークをオフラインにし、`001-pool-progression-tracker`の同期不良
   閾値時間を超えて待機する。
2. **期待結果**: 「startggとの同期がしばらく成功していません」のスナック
   バー通知が、モーダルの背後に表示され、モーダルの操作(対戦開始/
   スキップ/閉じる)を妨げない(FR-027)。
