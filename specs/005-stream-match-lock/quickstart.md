# Quickstart: 配信台設定された対戦の編集ロック

本featureが実装された後、start.gg上で配信台が設定された対戦カードの
編集がロックされることを確認するための手順。判定・ロックの詳細は
`data-model.md`・`contracts/stream-field-schema.md`を参照し、ここでは
重複させない。`001-pool-progression-tracker/quickstart.md`の前提条件
(devcontainer・`npm install`・startgg検証用トーナメント)を満たして
いることを前提とする。

## セットアップ

```bash
npm install
npm run dev   # Vite開発サーバーを起動(既定ポート 5173)
```

対象プールが初期化済みで、勝敗ブラケット(SINGLE_ELIMINATION/
DOUBLE_ELIMINATION)形式であること。start.ggの管理画面から、検証用の
対戦(Set)に配信台を1件割り当てておく。

## シナリオ1: 配信台が設定された対戦は編集できない(FR-002〜FR-004)

1. 管理画面の「データを再取得」を押し、配信台を設定した対戦の最新状態を
   同期する。
2. 一般モードの対戦カード一覧・組合せ図で、その対戦カードを確認する。
3. **期待結果**: 対戦カードをタップしても編集(進行中にする・対戦台の
   割り当て・結果入力)ができない。配信台が設定されていない他の対戦
   カードは、これまで通りタップして編集できる。

## シナリオ2: 配信中であることが表示で分かる(FR-007)

1. シナリオ1と同じ対戦カードを一覧・組合せ図で確認する。
2. **期待結果**: その対戦カードに、確定済み(修正不可)や進行中とは
   区別できる、配信中であることを示す表示(バッジ)が付いている。

## シナリオ3: 配信中の対戦は次戦候補に出ない(FR-006)

1. 配信台が設定されている対戦カードの出場者が両方確定していて未着手の
   状態にする(通常なら次戦候補になり得る状態)。
2. 対戦台に空きがある状態で「次戦候補」を確認する。
3. **期待結果**: 配信台が設定されている対戦カードは次戦候補として提示
   されない。他の(配信台が設定されていない)出場者確定済みの対戦が
   あれば、それが候補になる。

## シナリオ4: start.gg側の結果が反映される(FR-009)

1. start.gg上で、配信台が設定されている対戦の結果を確定させる。
2. 本ツールで同期(自動、最大60秒後。または管理画面の「データを再取得」)
   を待つ。
3. **期待結果**: 他の対戦カードと同様に、確定済みの結果(勝者・スコア)が
   一覧・組合せ図に反映される。

## シナリオ5: 配信台の解除でロックが解除される(FR-008)

1. start.gg上で、シナリオ1の対戦から配信台の設定を解除する。
2. 本ツールで同期(自動、最大60秒後。または「データを再取得」)を待つ。
3. **期待結果**: 配信中の表示が消え、通常どおり対戦カードをタップして
   編集できる状態に戻る。
