# Feature Specification: 配信台設定された対戦の編集ロック

**Feature Branch**: `005-stream-match-lock`

**Created**: 2026-08-18

**Status**: Draft

**Input**: User description: "外部から配信台設定されることがある。配信大設定
された場合は配信台側で進行が行われる。マッチがstartgg上でStreamが設定
されていたらマッチの編集はまったく行われずstartggからのデータ連携を待つ
のみにして。つまり進行中設定・対戦台設定・結果確定ができないようにして。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 配信対戦を誤って操作できないようにする (Priority: P1)

進行担当者は、大会運営の配信担当が外部(start.gg側)からある対戦を配信台に
割り当てた場合、その対戦がこのツール上の一覧・組合せ図に表示されていても、
「進行中にする」「対戦台を割り当てる」「結果を確定する」のいずれの操作も
行えないようにしてほしい。配信台に割り当てられた対戦は配信側のスタッフが
進行させるものであり、プール進行担当者が誤って結果を入力したり対戦台を
割り当てたりすると、配信側の進行と食い違いが生じるため。

**Why this priority**: 配信対戦への誤操作は、配信側の進行と本ツール上の
記録が食い違う・配信対戦の対戦台に別の対戦を誤って呼んでしまう等、大会
運営に直接影響する重大な事故につながる。単独で価値のある、最優先の防止策。

**Independent Test**: start.gg上で配信台が設定された対戦カードについて、
「進行中にする」ボタン・対戦台の選択・結果入力フォームがいずれも操作
できない(表示されない、またはグレーアウトして選択できない)ことを確認
する。配信台が設定されていない他の対戦カードは、これまで通り操作できる
ことも合わせて確認する。

**Acceptance Scenarios**:

1. **Given** start.gg上で配信台が設定されている未着手の対戦カード、
   **When** 進行担当者がその対戦カードをタップする、**Then** 「進行中に
   する」「対戦台の選択」「結果入力」のいずれも操作できない状態で表示
   される。
2. **Given** start.gg上で配信台が設定されている対戦カード、**When** その
   対戦が次戦候補(空いている対戦台に呼ぶべき対戦の提案)の対象になり
   得る状況になる、**Then** その対戦は次戦候補として提示されない
   (配信側で進行されるため、プール進行担当者が対戦台へ呼ぶ対象では
   ないため)。
3. **Given** start.gg上で配信台が設定されている対戦カード、**When** 定期
   同期によってstart.gg側の対戦結果(勝者・スコア)が反映される、
   **Then** 通常の対戦結果と同様に、確定済みの結果として一覧・組合せ図に
   表示される。
4. **Given** start.gg上で配信台が設定されている確定済み(結果入力済み)の
   対戦カード(後続対戦は未進行で、本来なら結果を修正できる状態)、
   **When** 進行担当者がその対戦カードをタップする、**Then** 結果の修正
   操作も含め、一切操作できない状態で表示される。

---

### User Story 2 - 配信対戦であることが一目でわかる (Priority: P2)

進行担当者は、ある対戦が配信台に割り当てられているために操作できないのか、
それとも別の理由(既に確定済み・後続の対戦が進行中等)で操作できないのかを、
対戦カードを見ただけで区別できるようにしてほしい。

**Why this priority**: User Story 1(操作をブロックすること自体)がなければ
そもそも意味を持たないためP2とする。ただし、理由が分からないまま操作でき
ないカードがあると「不具合ではないか」という問い合わせや、配信対戦の
存在に気づかず対戦台を別件で埋めてしまう等の運用ミスにつながるため、早期に
必要。

**Independent Test**: 配信台が設定されている対戦カードに、他の操作不可能な
理由(確定済み・後続進行中)とは異なる、配信中であることを示す表示が
付いていることを確認する。

**Acceptance Scenarios**:

1. **Given** start.gg上で配信台が設定されている対戦カード、**When** 一覧・
   組合せ図を表示する、**Then** その対戦カードに、配信によって進行中で
   あることを示す表示(バッジや注記)が付く。
2. **Given** start.gg上で配信台の設定が解除された対戦カード、**When** 次回
   の定期同期が完了する、**Then** 配信中であることを示す表示が消え、
   通常どおり操作できる状態に戻る。

---

### Edge Cases

- 総当り(ROUND_ROBIN)形式のプールは現在このツール自体が非対応(別途
  非対応化済み)のため、本仕様の対象外とする。
- 対戦カードが既に確定済み(結果入力済み)の場合でも、配信台が設定
  されている間は結果の修正操作を行えない。後続対戦の進行によるロック
  (`isLocked`)とは独立して適用され、たとえ`isLocked`がfalse(後続対戦が
  未進行で本来なら修正できる状態)であっても、配信台が設定されている
  限り修正はできない。配信が終了し配信台の設定が解除されれば、次回の
  定期同期で通常どおり修正できる状態に戻る(FR-008)。
- ある対戦カードについて、進行担当者がこのツール上で既に「進行中にする」
  操作や対戦台の割り当てを行い、その反映がまだstart.ggへ送信・同期
  されていない状態で、外部(配信担当)がstart.gg上でその対戦に配信台を
  設定した場合、次回の定期同期でその変更点(進行中状態・対戦台)は通常
  どおり送信を試みる。送信後は配信ロックの対象となり、それ以降の新たな
  編集はできなくなる。
- 対戦カードに配信台が設定されているかどうかの判定は、定期同期で取得
  した最新の情報を用いる。同期に失敗している間は、直前に取得できていた
  情報(配信中かどうか)をそのまま維持する(001-pool-progression-tracker
  のFR-012の既存方針=通信不可が操作を止めない、に準じる)。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、定期同期の際に、各対戦カードについてstart.gg上で
  配信台が設定されているかどうかを取得し、記録しなければならない。
- **FR-002**: システムは、配信台が設定されている対戦カードについて、
  「進行中にする」操作を行えないようにしなければならない。
- **FR-003**: システムは、配信台が設定されている対戦カードについて、
  対戦台の割り当て・変更を行えないようにしなければならない。
- **FR-004**: システムは、配信台が設定されている対戦カードについて、
  結果の入力(新規確定)および結果の修正(確定済みの結果の変更)のいずれも
  行えないようにしなければならない。この制限は、後続対戦の進行による
  修正ロック(`isLocked`)とは独立して適用される(`isLocked`がfalseで
  あっても、配信台が設定されている限り修正できない)。
- **FR-005**: システムは、配信台が設定されている対戦カードを、一覧・
  組合せ図から非表示にしたり除外したりしてはならない。表示はそのまま
  行い、操作のみを禁止する。
- **FR-006**: システムは、配信台が設定されている対戦カードを、次戦候補
  (対戦台への呼び出し提案)の対象から除外しなければならない。
- **FR-007**: システムは、配信台が設定されている対戦カードに、他の操作
  不可理由(確定済み・後続対戦の進行による修正ロック)とは区別できる、
  配信中であることを示す表示を行わなければならない。
- **FR-008**: システムは、start.gg側で配信台の設定が解除されたことを
  次回の定期同期で検知した場合、当該対戦カードの配信ロックを解除し、
  通常どおりの操作を可能にしなければならない。
- **FR-009**: システムは、start.gg側から取得した対戦結果(勝者・スコア・
  失格等)については、配信台が設定されている対戦カードであっても、
  他の対戦カードと同様に通常どおり反映しなければならない(結果の
  反映を妨げてはならない)。
- **FR-010**: システムは、配信台の設定状況を取得できない(同期に失敗
  している)間は、直前に取得できていた配信ロックの状態を維持しなければ
  ならない。

### Key Entities *(include if feature involves data)*

- **配信台の割り当て状況**: 対戦カードが、start.gg上で配信(ストリーム)に
  割り当てられているかどうかを表す状態。対戦台(物理的な卓)の割り当てとは
  別の概念であり、両者は同時に成立しうる(配信台が割り当てられている
  対戦でも、start.gg上に対戦台番号が別途記録されている場合がある)。
  定期同期のたびにstart.ggから取得し直す、ローカルでは編集しない読み取り
  専用の情報として対戦カードに保持する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: start.gg上で配信台が設定されている対戦カードに対する
  「進行中にする」「対戦台の割り当て」「結果確定」の操作の成功件数は、
  常に0件である。
- **SC-002**: start.gg上で配信台が設定されている対戦カードが、次戦候補
  として提示される件数は、常に0件である。
- **SC-003**: 進行担当者が対戦カード一覧を見ただけで、配信中の対戦と
  それ以外の操作不可の対戦(確定済み・後続進行中)を区別できる。
- **SC-004**: start.gg上で配信台の設定が解除されてから、次回の定期同期
  (最大60秒後)以内に、当該対戦カードの操作が可能な状態に戻る。
- **SC-005**: 配信台が設定されている対戦カードについても、start.gg側で
  確定した結果は、他の対戦カードと同じタイミング(定期同期)で本ツール上
  にも反映される。

## Assumptions

- 「配信台」は、start.gg上でその対戦(Set)に紐づけられる配信
  (ストリーム)の設定を指す。会場の物理的な対戦台(卓、既存の対戦台
  設定機能)とは別の概念であり、本仕様は配信の設定有無のみを対象と
  する。
- 配信台の設定・解除自体は本ツールの外(start.gg側、配信担当者)で行われ、
  本ツールはその状態を定期同期で取得して反映するのみで、本ツール内から
  配信台を設定・解除する機能は提供しない。
- 配信ロックの対象は、対戦カードの状態(未着手・進行中・確定済み)を
  問わない。確定済みの対戦カードであっても、配信台が設定されている間は
  結果の修正(001-pool-progression-trackerの結果修正ロック機能)を行え
  ない。後続対戦の進行によるロック(`isLocked`)とは独立した、別条件と
  して適用される(両方が同時に成立しうる)。
- 対戦台(物理的な卓)の割り当てと配信台の割り当ては独立して存在しうる
  情報であり、本仕様は配信台が設定されている場合の編集禁止のみを規定
  する。配信台が設定されていない対戦カードの挙動(既存の対戦台割り当て・
  次戦候補等)には一切変更を加えない。
- 総当り(ROUND_ROBIN)形式のプールは既に非対応のため、本仕様の対象は
  勝敗ブラケット形式(SINGLE_ELIMINATION/DOUBLE_ELIMINATION)のプールに
  限る。
