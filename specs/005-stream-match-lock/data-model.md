# Data Model: 配信台設定された対戦の編集ロック

`001-pool-progression-tracker/data-model.md`(および
`002-match-scoring-and-flow`)で定義済みのエンティティ(MatchCard等)を
拡張する。ここでは追加されるフィールドのみを記載し、既存フィールドは
再掲しない。

## 1. MatchCard(対戦カード)への追加フィールド

| フィールド | 型 | 説明 | 検証ルール |
|---|---|---|---|
| isStreamed | boolean | start.gg上でこの対戦(Set)に配信(ストリーム)が
  割り当てられているか(FR-001)。読み取り専用で、本ツール内から直接
  変更する手段は提供しない | 既定`false` |

**値の出所・更新契機**: 定期同期(`Q2. 対象プールの詳細・対戦カード一覧の
取得`)のたびに、start.gg側の最新値でそのまま上書きする(research.md #1)。
`tableNumber`のようなローカル優先の保護は行わない(配信台の設定・解除は
本ツールの外で行われるものであり、ローカルに「保護すべき編集内容」が
存在しないため)。

**`isLocked`(既存フィールド)との違い**: `isLocked`は「確定済みの対戦
カードを、後続対戦の進行を理由に修正できない」状態を表す
(001-pool-progression-trackerで導入)。`isStreamed`は「未着手・進行中の
対戦カードであっても、配信台が設定されているため新規の編集ができない」
状態を表す、独立した別のフラグ(research.md #2)。両者は同時に成立しうる
(配信中かつ確定済みの対戦カード等)が、判定・表示はそれぞれ独立して行う。

**`tableNumber`(既存フィールド)との違い**: `tableNumber`は会場の物理的な
対戦台(卓)を表す。`isStreamed`は配信(ストリーム)の割り当て有無を表す、
独立した別概念。配信台が設定されている対戦カードにも、start.gg上に
物理的な対戦台番号が別途記録されている場合があり、両者は互いに影響しない
(spec.md Key Entities)。

**同期失敗時の扱い**: 同期に失敗した場合、`isStreamed`を含む対戦カード
全体はローカルに保存済みの直前の値を維持する(既存の`runSync`の失敗時
挙動=ローカルデータを一切変更しない、をそのまま踏襲。research.md・
spec.md FR-010)。

## 2. 状態遷移

`isStreamed`は`status`(`NOT_STARTED → IN_PROGRESS → COMPLETED`)とは
独立した、`true`/`false`を行き来するだけのフラグ。定期同期のたびに
start.gg側の最新値へ更新される(値自体に一方向の遷移はない)。

| 状態 | 対戦カードの編集可否への影響 |
|---|---|
| `isStreamed === false` | 既存の規則(`isLocked`・プレビューモード)のみに従う。本仕様による追加のロックはない |
| `isStreamed === true` かつ `status !== "COMPLETED"` | 「進行中にする」「対戦台の割り当て」「結果確定」のいずれも実行不可(FR-002〜FR-004)。次戦候補の対象からも除外(FR-006) |
| `isStreamed === true` かつ `status === "COMPLETED"` | 既存の確定済みカードの表示・修正可否規則(`isLocked`)がそのまま適用される。配信中であることを示す表示(FR-007)は引き続き行う |
